Interactive Node Merging

This page provides a browser-side node-merging module for the example CLL network. The user selects the treatment components to merge, gives the merged node a new name, chooses the CNMA model, and presses Run node merging. The code is hidden from the user; only the controls, network plot, and results are shown.

The first execution may take some time because R and the required packages are loaded in the browser through WebAssembly. This module does not save user choices or create permanent analysis versions.

Select components to merge

components_all = [
  "Acal", "BR", "Clb", "FCR", "I", "Ibr", "O", "R", "Ven", "Zanubrutinib"
]

viewof components_to_merge = Inputs.checkbox(
  components_all,
  {
    value: ["Acal", "Zanubrutinib"],
    label: "Components to merge"
  }
)

viewof new_node_name = Inputs.text({
  value: "SecondGenBTKi",
  label: "New merged component name"
})

viewof cnma_model = Inputs.radio(
  ["Additive", "Additive + Interaction"],
  {
    value: "Additive",
    label: "CNMA model"
  }
)

viewof run_analysis = Inputs.button("Run node merging")

Validation rules

Rule Behaviour
Fewer than 2 components selected Stop
Empty merged node name Stop
Merged node name identical to one of the selected components Stop
Self-comparison created, e.g. A vs A Stop
A study becomes single-arm/non-comparative Stop
Fewer than 3 treatment nodes remain Stop
Network becomes disconnected Warning, but the analysis is allowed to continue
Duplicate comparisons are created within the same study Pool using inverse-variance weights

Notes for thesis interpretation

This is a client-side sensitivity module. It allows users to perform controlled node merging on the embedded example dataset, but it does not save choices to a database and does not create a permanent version history. For a full Living NMA platform with uploaded datasets, persistent versions, and user sessions, the Shiny/server version remains the correct production architecture.
